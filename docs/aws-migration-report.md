# AWS Migration Report

## Outcome

Runtime data now comes from real AWS services. The backend contains no local
movie repository and no local ranking provider. Existing API URLs, request
schemas, response schemas, authentication states and DynamoDB keys remain
unchanged.

## Repository audit

The audit found:

- production composition used DynamoDB for four tables but did not inject
  `PopularMoviesRepository`
- guest catalog order came from a Movies scan instead of PopularMovies
- the recommendation provider ranked local sample movies
- cache enrichment performed one `GetItem` per movie
- S3 settings existed without a transfer boundary or startup resource check
- the SageMaker class was not connected to the provider abstraction
- ML AWS YAML and systemd units contained resource identifiers
- the ML interaction exporter expected obsolete field/table names
- one deployed cache record was generated by the retired local provider
- deployed PopularMovies genre lists contain numeric movie references

## Repositories migrated

| Repository | Current AWS behavior |
|---|---|
| MoviesRepository | DynamoDB CRUD, paginated Scan, ordered/chunked/retried BatchGet |
| PopularMoviesRepository | DynamoDB CRUD/Get with read-only numeric ID normalization |
| UsersRepository | DynamoDB CRUD; identity scan only because no GSI exists |
| UserInteractionsRepository | Conditional writes and Query by user |
| RecommendationCacheRepository | DynamoDB CRUD/upsert; canonical read mapping; retired-provider cache rejected |

`InMemoryMovieRepository` and its local movie records were removed.

## Recommendation migration

- `MockRecommendationProvider` was removed.
- Guest browsing uses configured PopularMovies → Movies BatchGet.
- Returning users use RecommendationCache → Movies BatchGet.
- Cache misses use `SageMakerRecommendationProvider`.
- The provider invokes `sagemaker-runtime` using the source-backed
  `RecommendationEngine` contract.
- Users and UserInteractions build onboarding/returning request context.
- Endpoint errors map to controlled HTTP 502/503/504 responses.
- Cache read/write failures are non-fatal to a successful model response.
- No fake ranking is written to RecommendationCache.
- Endpoint model versions take precedence over the environment fallback.

## S3 migration

- added a real boto3 S3 storage boundary
- added backend upload/download/list CLI
- made raw data part of ML S3 synchronization
- moved ML Region, bucket and prefixes to canonical environment variables
- updated SageMaker/EC2 launch paths to receive an environment file
- backend startup verifies bucket and prefix-list permission
- backend HTTP handlers never load dataset objects

## Configuration updated

- startup identity/resource validation through STS, DynamoDB, S3 and optional
  SageMaker control plane
- exact DynamoDB key-schema comparison
- required PopularMovies `list_id`
- required environment-specific S3 prefixes
- optional SageMaker enablement gate
- endpoint media type and result limit
- production Docker reload default disabled
- Compose restart policy enabled

## Remaining deployment verification

The Docker credential chain successfully reached SageMaker in
`ap-southeast-1`. However, read-only checks returned no endpoints, endpoint
configurations, or SageMaker model resources in the configured account/Region.
`DescribeEndpoint(movie-rec-endpoint)` returned `ValidationException`.
Therefore no live inference claim is made.

4. invoke onboarding and returning-user contract requests
5. confirm the deployed artifact uses the same contract as
   `ml/src/recommenders/engine.py`

repository. Live invocation remains unchecked because the configured
