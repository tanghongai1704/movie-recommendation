# Amazon S3

S3 is the durable source of truth for datasets, features, training inputs,
model artifacts and outputs. Backend request handlers never load datasets.

## Configured structure

The real physical prefixes are environment-specific. Their logical roles are:

```text
movie-recommendation-fcaj/
├── datasets/                 AWS_S3_DATASET_PREFIX
│   ├── raw/                  AWS_S3_RAW_PREFIX
│   ├── processed/            AWS_S3_PROCESSED_PREFIX
│   ├── serving/              DynamoDB table exports
│   └── exports/              AWS_S3_INTERACTION_EXPORT_PREFIX
├── training/                 AWS_S3_TRAINING_PREFIX
├── models/                   AWS_S3_MODEL_PREFIX
│   └── bundles/<version>/model.tar.gz
├── inference/                AWS_S3_SERVING_PREFIX
├── evaluation/               AWS_S3_OUTPUT_PREFIX
└── logs/
```

Feature tables share `datasets/processed/`; no separate feature-prefix
variable is needed. `datasets/serving/` contains DynamoDB exports, whereas
`inference/` contains the lookup tables loaded by RecommendationEngine.

| Prefix | Purpose |
|---|---|
| Dataset | Logical root for data assets |
| Raw | Immutable source datasets and lineage |
| Processed | Cleaned normalized datasets |
| Features | Materialized feature tables inside Processed |
| DynamoDB exports | JSONL snapshots under `datasets/serving/` |
| Inference | Endpoint lookup tables under `inference/` |
| Training | Splits and training job input |
| Model | Versioned model artifacts and manifests |
| Output | Evaluation reports and job outputs |
| Interaction export | DynamoDB interaction exports for retraining |

## Upload and download

Backend operational CLI:

```bash
cd backend
python scripts/s3_dataset.py list raw
python scripts/s3_dataset.py upload raw /path/to/movies.csv
python scripts/s3_dataset.py download serving movies.jsonl /tmp/movies.jsonl
```

ML directory synchronization:

```bash
cd ml
python scripts/aws_sync.py list
python scripts/aws_sync.py push --dry-run
python scripts/aws_sync.py push
python scripts/aws_sync.py pull --only raw processed features splits serving
```

`ml/configs/aws.yaml` contains logical mappings only. Region, bucket, every
prefix, table name and SageMaker resource identifier come from the same
canonical environment variables as the backend.

Downloaded files are an ephemeral processing workspace. They are never bundled
into the backend image or used as request-time fallback data.

## Interaction export

```bash
cd ml
python scripts/export_interactions.py --upload
```

The exporter reads the deployed `UserInteractions` schema, converts
`reaction/set/1` to `like`, `reaction/set/-1` to `dislike`, ignores clear
events, and uploads JSONL to `AWS_S3_INTERACTION_EXPORT_PREFIX`.

At larger scale, use DynamoDB point-in-time export to S3 instead of scanning the
entire table.

## Security and lifecycle

- Block all public access.
- Enable server-side encryption.
- Use bucket versioning for model manifests and artifacts.
- Apply lifecycle expiration to temporary training/output objects.
- Restrict backend access to list/head plus explicitly required object actions.
- Restrict SageMaker to the configured training/model/output prefixes.
- Log sensitive data access with CloudTrail data events when required.

## Required IAM permissions

Read-only backend startup validation:

- `s3:GetBucketLocation`
- `s3:ListBucket`

Dataset tooling and training additionally require:

- `s3:GetObject`
- `s3:PutObject`
- `s3:AbortMultipartUpload`
- `s3:ListBucketMultipartUploads`

Grant `s3:DeleteObject` only to lifecycle/administrative roles.

## Verification

```bash
aws s3api head-bucket --bucket "$AWS_S3_BUCKET"
aws s3api list-objects-v2 \
  --bucket "$AWS_S3_BUCKET" \
  --prefix "$AWS_S3_RAW_PREFIX" \
  --max-items 1
aws s3api get-bucket-encryption --bucket "$AWS_S3_BUCKET"
aws s3api get-public-access-block --bucket "$AWS_S3_BUCKET"
```
